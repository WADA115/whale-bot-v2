# 小鲸鱼框架总览

## 设计原则

- 角色层只写身份、关系、边界、驱动力、说话方式，不写数值、分数、固定台词、动作枚举或函数。
- 运行时负责工具、权限、超时、日志和状态，不把运行时规则伪装成角色的一部分。
- 群聊与私聊共用同一个角色、同一份记忆上下文和同一套回复流程。
- 需要权限的事先问，不硬闯；需要时间的事放后台，不阻塞当前对话。
- 不把私聊内容复述到群里，也不把群里的私事当成公开信息。

## 主要模块

```text
src/app.js                 运行时装配、消息分发、权限审批、跨会话上下文
src/config.js              配置、角色卡、密钥和路径装载
src/runtime/actor-turn.js  角色回合编排（231 行）
src/runtime/actor-*.js    上下文 / 工具 / 媒体 / 回复子模块
src/runtime/notices.js     唤醒、状态和临时提示
src/runtime/live-group.js  群聊现场感知
src/character/             角色卡、场景、黑话、表情、表达
src/mind/                  内在状态、心跳、发呆、离线后的连续感
src/story/                 关系、共同经历、叙事编辑
src/core/                  模型路由、语音、权限、搜索、日志等基础能力
src/platform/              B站、QQ空间等平台动作
src/http/routes.js         路由分发
src/http/routes/*.js       按域拆分的 API
scripts/                   启动、看门狗、本机路径
```

## 一次回合

```text
收到消息
→ 记录到共享会话流
→ 识别是否在回应权限请求
→ 判断要不要处理
→ 组装角色上下文
→ 合并：当前会话历史、其他会话近况、记忆、黑话、知识、图片/语音描述
→ 模型选择：直接回复 / 调工具
→ 发送
→ 记录发出的文字
```

角色提示只负责“她是谁、怎么说话、边界在哪”。  
工具调用和权限由运行时执行。

## 共享上下文

所有私聊和群聊进入同一个环形会话流：

```text
最近 80 条进出消息
每次回复带最近 12 条其他会话作为背景
```

作用：

- 不会出现“群里的她”和“私聊的她”两套人格。
- 群聊里知道私聊刚发生什么，私聊里也知道群聊近况。
- 只作为内部背景，不自动跨会话复述。

私聊内容进入群聊提示时，会明确标注“不要复述私事”。

## 权限

权限是一条可以双向修改的临时许可：

```text
她请求 → 群聊 + 私聊同时收到
任一方批准 → 生效
任一方拒绝 → 不阻断另一方
双方都拒绝 → 关闭
批准后任一方可撤回
```

支持自然口语：

```text
行
可以
拿去
算了
不给
再加 20 分钟
减 10 分钟
改成 10 分钟
不要私聊
不要群聊
```

默认范围是群聊和私聊都开；  
可以用口语排除其中一边。  
默认时长三十分钟，可以口头加减或改绝对值。

也可以由主人主动给许可，不必等她先请求。

权限只改变“允许做什么”，不自动执行工具。  
真正的发送、发帖、评论仍要对应工具和能力。

## 语音

当前链路：

```text
Edge 中文 → RVC ATRI
```

特点：

- 清楚。
- 不调情。
- 情绪平。

满穗语音模型保留但关闭，原因是本机内存不足，s1 训练无法稳定完成。  
语音服务不常驻，按需启动，闲置后关闭。

## 信息获取与非阻塞

- 本地检索是同步的短查询，不依赖网络。
- 黑话联网核验在后台队列里做，不挡正常回复。
- 权限判断在后台做，不等待模型返回才回复当前消息。
- 语音冷启动只影响语音工具本身，不影响文字。
- 外部平台动作有超时，失败只影响该工具，不拖垮整轮。
- 共享会话流是内存环形结构，读写不阻塞。

## 状态与隐私

不会进入开源仓库的内容：

```text
config.json
state/
state/secrets.json
state/bilibili.json
state/logs/
state/voice/
scripts/local.paths.ps1
```

仓库内的示例配置只保留占位符。  
角色卡没有真实姓名、QQ 号、密钥或本机路径。

## 已知未完成

- s1 语气训练受本机内存限制，未完成。
- GitHub 推送受网络限制，本地提交未推远端。
- 真实 QQ 语音、群聊 canary、QQ 空间和 B 站评论还没有做最终实机验证。
- 群权限审批人的限制做成配置项，默认仍允许群内任何人批准。
- 面板的权限中心已能查看和操作，但样式仍是最简实现。

## 结论

当前框架的重心不是堆功能，而是：

```text
一个角色
一套记忆
一个共享上下文
一套权限
工具在后台，不挡对话
```

角色层保持干净；  
运行时承担复杂度；  
需要人类点头的事，先问再动。
